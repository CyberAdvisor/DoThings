# Do Things change log

Newest first. History before v1.0.0 is in the git log.

- **v1.9.2 (2026-11-10):** Text looks like Things': it's drawn without the extra smoothing the browser adds to light text on a dark background, so it's crisper. The dark appearance now uses Things' colors: white task titles, Things' lighter gray for the second line, counts and labels, and Things' background.
- **v1.9.1 (2026-11-10):** The sidebar has a space between the last saved search and the Hide Completed and Hide Empty checkboxes, like the one above the Searches heading.
- **v1.9.0 (2026-11-10):** **Saved searches.** Build your own searches in the sidebar: click **+** beside the Searches heading, or open a search and click **Edit search**. A search covers Today or all open tasks and can use priority (any of the ones you pick), tags (any of them), text in the title or notes, projects and areas (any of them) and an overdue deadline; a task must match everything you set. The builder shows the matching tasks as you choose, before you save. Searches can be renamed, changed and deleted (after confirming); your tasks are never changed. The fixed P1–P4 and Overdue searches are now your starting searches, editable like any other. A search that can list more than one priority shows each task's priority as a colored pill. The Searches heading collapses and expands the list, and your browser remembers it. Searches are saved in `searches.json`; copy it along with your other files when you update.
- **v1.8.0 (2026-11-10):** **Calendar events in Today**, as in Things. Turn on **Settings › Calendar events › Show calendar events in Today** and today's events from macOS Calendar appear above the priority groups: all-day events first, then timed ones in order, each with its time, title and calendar color. Events that have ended are dimmed, and the one happening now has its time in red. Click an event to open it in Calendar. Choose which calendars to show in the same section (new calendars show until you uncheck them). Do Things only reads your calendars, never changes them. It's off until you turn it on; turning it on is what makes macOS ask whether Terminal (or Shortcuts) may access your calendars. If access is off, Today shows an amber notice with the steps. `debug_calendar.py` now uses the same script as Do Things, and its `--applescript` option is gone.
- **v1.7.1 (2026-11-10):** No change to how Do Things works. New read-only `debug_calendar.py` checks whether Do Things could show today's calendar events in Today, as Things does: it reports whether macOS lets Terminal read your calendars (the first run may ask), the calendars it sees, today's events and how long reading them took. `--applescript` also times reading through the Calendar app for comparison; `--hide-titles` hides event titles. Nothing is written to Calendar, Things or Do Things' files.
- **v1.7.0 (2026-11-10):** Sequential projects are now set up in **Settings › Sequential projects**: list the project tags you use in Things, each with a priority. A project with one of those tags is worked one task at a time, as before (start, undo, "task N of M", Reset other tasks), and its tasks get the priority set beside the tag. `Sequential` and `Next Up` are no longer built in, and the list starts empty. Settings shows whether each tag exists in Things, and Today shows an amber notice naming any listed tag that doesn't, with a link to Settings; only that tag's projects are skipped. A project with two listed tags uses the higher priority, and Do Things no longer removes `Next Up` from a project also tagged `Sequential`: it never changes projects now. Changing a tag's priority leaves tasks already started as they are; removing a tag stops its projects (their tasks are no longer undone), and adding it back picks up where they were. **Action needed:** to keep working as before, open Settings › Sequential projects and add `Sequential` with P2 and `Next Up` with P4. Until you do, those projects start nothing new; tasks already in progress stay where they are.
- **v1.6.0 (2026-11-10):** A fifth priority, **P5**, below Next Up, and a new **Priorities** section in Settings. Give each priority your own name; the names appear on Today's group headers and on priority pills, and a priority with no name (P5 to start) shows just its tag. Settings also shows whether each tag exists in Things. **Auto assign due and overdue tasks P1** (on by default) can be turned off: then a due task keeps its priority, and moving a task into or out of P1 leaves its deadline alone. **Assign priority … to new Today tasks** chooses the priority a Today task without a P tag gets (P2 to start; tasks of Next Up projects still get P4). Settings are saved as you change them, in `settings.json`; copy it along with your other files when you update. In the Overdue search, each task's priority now shows as a colored pill with its name (Due Today red, To Do blue, Follow Up amber, Next Up teal, P5 purple), set apart from the gray tag pills. The sidebar tagline is now "Turning Plans Into Action". **Action needed:** create a tag named `P5` in Things (Window › Tags). Until it exists, Do Things makes no automatic changes and shows how to create it.
- **v1.5.0 (2026-11-08):** **Move to Trash** in the editor of an open task. Click it, then confirm in the card, and the task goes to Things' Trash (put it back from the Trash in Things if you change your mind). Things' URL commands can't delete, so Do Things asks Things through AppleScript. **Action needed:** the first time, macOS asks whether Terminal (or Shortcuts, if you start Do Things from the shortcut) may control Things; click **Allow**. If you missed it, turn on **Things3** under System Settings › Privacy & Security › Automation › Terminal (and Shortcuts).
- **v1.4.0 (2026-11-08):** A task with a reminder shows its time in small gray text after its title, for example "Call dentist 2:30 PM", in Today and the searches. The task's editor shows the time after the date on the When line. Reminders are still set and changed in Things. If you change a task's When in Do Things, the reminder isn't shown until Things confirms the change; then it shows whatever Things kept.
- **v1.3.1 (2026-11-08):** No change to how Do Things works. `debug_things.py` now prints the reminder time of each Today task that has one, as Things stores it and as Do Things reads it, and a count at the end. This checks the format before reminder times are shown in the task list.
- **v1.3.0 (2026-11-08):** New **Hide Empty** checkbox in the sidebar, under Hide Completed. When it's checked, Today's priority groups with no tasks are hidden. With Hide Completed also checked, a group whose only tasks are completed ones is hidden too. While you drag a task, the hidden groups reappear so you can drop it into any priority. The setting is remembered in your browser, like Hide Completed.
- **v1.2.0 (2026-11-08):** **Reset other tasks** for Sequential and Next Up projects. If more than one task of such a project is in Today, open the one to keep and click **Reset other tasks**. Do Things shows which tasks will go back to Anytime and does nothing until you click **Reset**. Every other task of that project in Today then goes back to Anytime without its P tag (tasks with a deadline are left alone), and the kept task becomes the one in progress. The returned tasks keep their place in the project, so check the project's order in Things afterwards. Also: any task of a Next Up project that is in Today without a P tag is now P4, not P2, including tasks you dated yourself.
- **v1.1.0 (2026-11-08):** New priority **P4 Next Up** and **Next Up projects**. Next Up is for lower-priority projects that don't need immediate action but that you want to be reminded of, such as books to read, shows to watch or chores to do. Tag a Things project `Next Up` and it works like a Sequential project: its next task, in project order, gets a start date of today and the `P4` tag, and shows in a new **Next Up** group below Follow Up. One task at a time, with the same "task N of M" marker and undo. A project tagged both `Sequential` and `Next Up` stays Sequential, and Do Things removes its `Next Up` tag. The sidebar has a new **P4 · Next Up** search, and tasks can be dragged to Next Up or given P4 in the editor. **Action needed:** create a tag named `P4` in Things (Window › Tags). Until it exists, Do Things makes no automatic changes and shows how to create it. The README screenshot shows the new group.
- **v1.0.3 (2026-11-07):** No change to how Do Things works. The repository's commit history was rewritten to remove a local computer address and AI session links from commits; if you cloned Do Things before this, run `git fetch origin && git reset --hard origin/main` (or clone it again).
- **v1.0.2 (2026-11-07):** Setup corrected: Terminal needs the same permission as the shortcut, **Data shared by Things and affiliated apps** (System Settings › Privacy & Security › Files & Folders › Terminal, or **Allow** when macOS asks), not Full Disk Access.
- **v1.0.1 (2026-11-07):** Setup now covers the permission the Do Things shortcut needs: the first time it runs, macOS asks whether Shortcuts may access data from other apps (click **Allow**), or you turn on **Data shared by Things and affiliated apps** and **Documents** for Shortcuts in System Settings › Privacy & Security › Files & Folders. The change log moved out of the README into `CHANGELOG.md`, and history before 1.0 was removed from it and from each file (it remains in git).
- **v1.0.0 (2026-11-07):** Do Things uses your Mac's own time zone for "today" instead of Mountain Time, so it works wherever you are. The sidebar has a title, **Do Things**, with the tagline "Getting Things Done in Things", and the version at the bottom of the sidebar opens this guide. **Security fix:** if Do Things couldn't hand a change to Things (the `open` command failed or timed out), the line it wrote to `errors.log` included your Things auth token. It now records only what went wrong. If your `errors.log` contains lines starting "Could not open Things URL", delete the file; to be thorough, also replace the token in Things (Things › Settings › General › Manage) and save the new one in Do Things' Settings. The README is rewritten for people downloading Do Things: why it exists, a screenshot of Today, its advantages over Things, installing from a release, running it from a shortcut, cloning it to change it, and reporting problems.
